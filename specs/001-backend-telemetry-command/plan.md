# Implementation Plan: Backend Telemetry Enrichment & Manual Override

**Branch**: `001-backend-telemetry-command` | **Spec**: `specs/001-backend-telemetry-command/spec.md`
**Input**: Feature specification from `/specs/001-backend-telemetry-command/spec.md`

## Summary

Two tightly-coupled features that unblock the mobile app manual override (FR-010a, FR-022a):

1. **Enriched Telemetry (FR-010a/b)**: Add `velocity_vector` (m/s) and `fsm_state` fields to
   every `sentry/telemetry` MQTT message. Backend converts `TrackedTarget.velocity_vector`
   from pixels/frame to m/s using the pinhole camera model + LRF distance.

2. **Manual Override Subscriber (FR-022a)**: New `CommandSubscriber` component subscribes to
   `sentry/command`, validates `sentry_id`, forwards pan/tilt velocities to `TurretManager`
   during `MANUAL_OVERRIDE` state, enforces 3-second safety timeout and 20 Hz rate limit.
   Both components use TLS (port 8883) with username/password credentials.

## Phase 0 — Research (completed)

See `research.md` for full findings. Summary of key decisions:

| Decision | Chosen Approach | Reference |
|----------|-----------------|-----------|
| TLS paho-mqtt | `tls_set(cert_reqs=ssl.CERT_NONE)` + `tls_insecure=True` for self-signed broker | research.md §1 |
| velocity m/s conversion | Pinhole model: `v_m_s = (v_px_frame * lrf_m) / (focal_px * fps)` | research.md §2 |
| Override thread-safety | `threading.Lock` + `bool` flag; `enter_override()` / `exit_override()` on `SentryBrain` | research.md §3 |
| Rate limiting | Timestamp-based: skip commands within 50 ms of the previous | research.md §3 |
| `CAMERA_FPS` | Add `CAMERA_FPS: int = 25` to `config.py` (from GST_PIPELINE `framerate=25/1`) | research.md §2 |
| `CAMERA_HFOV_DEG` | Add `CAMERA_HFOV_DEG: float = 120.0` to `config.py` (calibrate per deployment) | research.md §2 |

## Complexity Tracking

> No Constitution violations. All decisions within normal complexity budget.

| Concern | Mitigated By |
|---------|-------------|
| Thread-safety between CommandSubscriber and SentryBrain | `threading.Lock` on `_override` flag; `enter_override()` is the only mutation path |
| Vision pipeline not blocked by override | `CommandSubscriber` on daemon thread; lock acquire is O(1) |
| Backward compat on telemetry payload | `velocity_vector: null` and `fsm_state: "SCAN"` always present — consuming clients must handle `null` |
